# Prepositions Quiz --- учебный проект

> README фиксирует согласованные решения, проверенные этапы и следующий
> шаг.

## 1. Цель проекта

Создать графическую викторину для Windows и изучать Python на реальном
проекте --- от консольной версии к графическому приложению.

### Подтверждённые требования

-   В каждом вопросе ровно 3 варианта ответа.
-   Ровно 1 вариант правильный.
-   За правильный ответ начисляется 1 очко.
-   Некорректный ввод не должен пропускать вопрос: программа должна
    запросить ответ повторно.
-   Планируются графический интерфейс и анимации.
-   Сами вопросы не должны становиться сложнее; со временем варианты
    ответа могут становиться более похожими.

## 2. Согласованные технологии и среда

-   **Backend:** Python + FastAPI.
-   **Frontend:** React + TypeScript + Vite.
-   **Database:** SQLite для локальной разработки; PostgreSQL в Supabase
    для удалённой базы.
-   Существующую Python-логику игры сохраняем и используем в backend.
-   Способ упаковки в Windows-приложение пока не зафиксирован.

Зафиксированные версии (не предлагать обновление без обсуждения):

-   Python 3.12.10
-   Node.js v24.14.1
-   npm 11.11.0
-   FastAPI 0.162.0
-   SQLite 3.49.1
-   `psycopg[binary]` используется для подключения к PostgreSQL.

Среда: Windows, Visual Studio Code, PowerShell. Виртуальное окружение
Python: `.venv`.

## 5. Игровая логика и валидация

В `game_logic.py` вынесены функции:

-   `get_categories(questions)`
-   `get_questions_by_category(questions, category)`
-   `check_answer(user_answer, correct_answer)`
-   `calculate_score(results)`
-   `calculate_percentage(score, total_questions)`

Валидатор проверяет, в частности:

-   список вопросов не пуст;
-   обязательные поля присутствуют;
-   у каждого вопроса ровно три варианта ответа;
-   правильный ответ --- целое число от 1 до 3 (`bool` не принимается);
-   текст вопроса и варианты ответов не пустые;
-   категория указана корректно.

## 6. Backend API

Подтверждённые endpoints:

  ------------------------------------------------------------------------------------
  Метод                   Endpoint                             Назначение
  ----------------------- ------------------------------------ -----------------------
  `GET`                   `/`                                  Проверка работы API

  `GET`                   `/categories`                        Получение категорий из
                                                               базы данных

  `GET`                   `/questions`                         Получение вопросов;
                                                               можно передать
                                                               категорию

  `POST`                  `/quiz/session/`                     Создание игровой сессии

  `POST`                  `/quiz/answer`                       Отправка ответа в
                                                               рамках сессии

  `GET`                   `/quiz/session/{session_id}/score`   Получение результата
                                                               сессии
  ------------------------------------------------------------------------------------

### Правила API

-   `GET /questions` не должен раскрывать `correct_answer` или
    `full_answer`.
-   Ответ отправляется с `session_id`, `question_id` и `answer`.
-   На один вопрос в одной сессии можно ответить только один раз.
-   Сессия с выбранной категорией принимает вопросы только этой
    категории.
-   Повторная отправка возвращает **HTTP 409 Conflict**.
-   Неизвестная сессия или вопрос обрабатываются как ошибка
    отсутствующего ресурса.
-   Некорректные данные запроса проверяются FastAPI/Pydantic.
-   Завершённая сессия не принимает новые ответы.

### Установка зависимостей

## 7. Поддержка баз данных

Backend поддерживает два варианта:

-   **SQLite** --- локальная база `quiz.db`, используется, когда
    переменная окружения `DATABASE_URL` не задана.
-   **PostgreSQL (Supabase)** --- используется, когда задана переменная
    окружения `DATABASE_URL`.

Выбор базы выполняется функцией `is_postgres()` в `database.py`.

### Локальная SQLite

Для локальной разработки `DATABASE_URL` должна быть не задана в текущем
процессе PowerShell. Приложение использует локальный файл `quiz.db`.

При запуске FastAPI инициализация таблиц и начальных данных выполняется
для SQLite через lifespan приложения.

### Supabase PostgreSQL

Перед запуском backend задайте `DATABASE_URL` в PowerShell:

``` powershell
$env:DATABASE_URL = "your-supabase-postgresql-connection-string"
```

Запустите API в том же окне PowerShell:

``` powershell
python -m uvicorn api:app --reload
```

Важно:

-   Используйте строку подключения PostgreSQL из настроек Supabase.
-   Для подключения используется SSL (`sslmode=require`).
-   Для PostgreSQL используется пакет `psycopg`.
-   Таблицы и данные Supabase уже созданы; `create_tables()` и
    `seed_questions()` предназначены только для локальной SQLite.
-   Переменная окружения должна быть задана в том же процессе/окне
    PowerShell, из которого запускается Uvicorn.
-   Не публикуйте `DATABASE_URL`, пароль базы данных или содержимое
    `.env`. Не добавляйте секреты в Git или README.

Чтобы вернуться к SQLite в текущем окне PowerShell:

``` powershell
Remove-Item Env:DATABASE_URL
```

### Таблицы

-   `categories` --- категории;
-   `questions` --- вопросы и правильный номер ответа;
-   `answer_options` --- варианты ответов для вопроса;
-   `quiz_sessions` --- игровые сессии;
-   `quiz_results` --- ответы и результаты пользователя.

В Supabase при последней проверке находились 2 категории, 14 вопросов и
42 варианта ответа. Эти значения могут измениться при редактировании
базы.

### Основные функции `database.py`

-   `is_postgres()`
-   `get_connection()`
-   `database_connection()`
-   `placeholder()`
-   `create_tables()` --- локальная SQLite.
-   `seed_questions()` --- локальная SQLite.
-   `get_categories_from_db()`
-   `get_questions_from_db(category=None)`
-   `get_question_from_db(question_id)`
-   `create_quiz_session(category=None)`
-   `save_quiz_answer(session_id, question_id, selected_answer)`
-   `get_quiz_score(session_id)`

Повторная отправка ответа блокируется исключением
`QuestionAlreadyAnsweredError`.

Запуск всех тестов:

Запуск тестов API отдельно:


### Важно перед локальным запуском тестов

Тесты должны использовать локальную SQLite. Если `DATABASE_URL` задана в
текущем окне PowerShell, удалите её перед запуском:

``` powershell
Remove-Item Env:DATABASE_URL
```
